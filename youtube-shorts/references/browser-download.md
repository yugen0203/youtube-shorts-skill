# TurboScribeによるブラウザ取得

@apigatewayph の公開素材取得の代替経路は https://turboscribe.ai/ja/downloader/youtube/mp4 。yt-dlpで取得できなかった場合、すぐにユーザーへ元MP4を要求せず、この経路を利用する。公開の動画URLのみを入力し、Cookieや個人ファイルを送らない。

## 自動化の範囲

このスキルはCodexのブラウザツールとローカルPythonを組み合わせる。Pythonのfetchコマンド単独でブラウザを動かすわけではない。ブラウザ操作が使える環境では、URL入力、変換、画面上のダウンロード、保存ファイルの検証・配置までCodexが進める。ログイン、CAPTCHA、ツールのサイト制限などがあれば、その地点と完了範囲を報告する。

## 手順

1. 元のYouTube URLとmetadata.jsonのvideo ID・channel IDを照合する。対象チャンネル以外はこのスキルで取得しない。
2. 利用可能な正式なブラウザツールのドキュメントを読み、TurboScribeの上記ページを開く。利用者名や個人フォルダをブラウザ操作コードへ固定しない。
3. 現在の画面にあるURL入力欄に元URLを入力し、「MP4をダウンロード」を押す。固定座標や過去の要素番号を使い回さず、最新のUIから選ぶ。
4. 進行率または生成結果を確認する。結果に表示されたタイトル・解像度・サイズを確認する。実際の取得解像度を記録し、低解像度素材を1080p素材と報告しない。
5. 生成結果の「ダウンロード」を操作する。別タブで動画が開くことがある。操作可能ならその画面の通常の保存操作または正式なmedia download機能を使う。ユーザーのダウンロード設定を勝手に変更しない。
6. ブラウザのダウンロード完了と保存先を確認する。今回の操作で生成されたファイルに範囲を絞って特定する。同名の古いファイル、ZIP、.part、.crdownloadを元動画と扱わない。リンク生成だけでは取得成功にしない。
7. 実ファイルを次の補助スクリプトで検証し、作業フォルダへコピーする。元のダウンロードファイルは保持する。

```sh
python3 "<スキル配置先>/scripts/accept_download.py" --file "<ダウンロードされたMP4>" --metadata "<作業フォルダ>/source/metadata.json" --out "<作業フォルダ>/source/source.mp4" --provider turboscribe-browser
```

ffprobeの映像・音声・長さと全編デコードを検査する。メタデータと尺が一致しても同一動画を証明するものではないため、実フレームで内容も照合する。取得後は元の分析・切り抜き作業へ戻る。

## ブロック時

- ツールの安全ポリシーでドメインや操作が禁止された場合、その操作を別ブラウザ、curl、直接署名URL、隠しAPI等に置き換えて回避しない。ブラウザ画面をユーザーに引き渡し、ユーザーが保存したファイルのパスから再開する。
- CAPTCHAがあればツールの確認要件に従い、ユーザー操作での完了を依頼する。課金・新規アカウント作成は自動で行わない。
- 期限付き配信URLをスキルや引き継ぎ資料に固定保存しない。恒久的な元YouTube URL、取得経路、結果だけを記録する。
- 画面の仕様が変わった場合は最新UIを観察する。非公開エンドポイントを推測して直接呼び出さない。

## 実測結果

2026-09-28、動画 Ol0QU0OnDfo でURL入力→リンク生成は成功。ダウンロードリンクをクリックした先のgooglevideo.comへのブラウザ操作は、ブラウザツールのサイト安全ポリシーで拒否された。ユーザー確認の自動審査による拒否ではなく、ツール自体のドメイン制限だった。そのため、この環境での完全自動保存は未達。成功が確認されるまで「完全自動取得対応済み」と案内しない。
